# البنشر الذكي — الإصدار 1.0.1

**منصة البنشر وصيانة المركبات، مبنية على بنية «خدمات» مع الحفاظ على واجهات العميل ومقدم الخدمة ولوحة الإدارة.**

هذه النسخة تحتفظ ببنية الحسابات والصلاحيات، تسجيل العميل ومقدم الخدمة، اعتماد مقدمي الخدمة ووثائقهم، إنشاء الطلبات وإسنادها، متابعة الحالات، الموقع والمسارات، المحادثات والإشعارات، التقييمات والشكاوى، العروض والتقارير، وسجل العمليات. التغيير الأساسي هو تخصيص الكتالوج والهوية البصرية لمجال المركبات وإزالة الذكاء الاصطناعي.

## الخدمات الافتراضية

يعرض التطبيق قسمًا واحدًا فقط باسم **البنشر وصيانة المركبات** لتجنب توزيع الخدمات على أقسام عامة كثيرة. ويتضمن:

- إصلاح بنشر متنقل.
- تبديل إطار أو كفر.
- فحص البطارية وتشغيل المركبة.
- تغيير الزيت والفلاتر.
- ميكانيكي متنقل.
- كهربائي سيارات.
- سطحة ونقل مركبة.
- فحص مركبة مبدئي.
- خدمة أخرى للمركبات يصفها العميل.

يمكن للمدير تعديل الخدمات والأسعار ونماذج الطلب من لوحة الإدارة. وعند ترقية قاعدة بيانات سابقة، تُعطّل الأقسام العامة القديمة دون حذف الطلبات التاريخية، وتُنقل خدمات المركبات المعروفة إلى القسم المخصص.

## لا يوجد ذكاء اصطناعي

لا تتصل هذه النسخة بـ OpenAI أو بأي واجهة ذكاء اصطناعي. البحث عن الخدمات يعتمد على الكلمات المفتاحية والمرادفات المحلية، ويختار العميل الخدمة يدويًا من القائمة. لا توجد واجهة «اطلب لي» أو تحليل طلبات/صور بواسطة الذكاء الاصطناعي.

## الواجهات

- `/customer` — واجهة العميل.
- `/provider` أو `/provider.html` — واجهة مقدم الخدمة.
- `/admin` أو `/admin.html` — لوحة الإدارة.
- `/health` — فحص صحة الخادم.

الواجهات الثلاث جزء من تطبيق واحد، مع صلاحيات منفصلة. ويمكن تثبيتها كتطبيقات ويب تقدمية (PWA) بأيقونات مخصصة لكل واجهة.

## التشغيل المحلي

المتطلبات: Node.js 22.18 أو أحدث وnpm.

```bash
npm install
npm run build
npm start
```

يفتح التطبيق افتراضيًا على المنفذ `3000`.

## النشر على Railway

1. ارفع محتويات مجلد `albanshar-aldhaki` إلى مستودع GitHub.
2. اربط المستودع بخدمة Railway.
3. اربط **Volume دائمًا** بمسار `/app/data` حتى تبقى قاعدة البيانات وسر الجلسات محفوظين بعد إعادة إنشاء الحاوية.
4. اترك أمر البناء والتشغيل كما في `railway.toml`، أو استخدم `npm run build` و`npm start`.

لا تحتاج إلى إضافة `JWT_SECRET` أو `ADMIN_PASSWORD` يدويًا. ينشئ التطبيق سر الجلسات ويحفظه في `data/.jwt-secret` إذا لم يكن محددًا في البيئة. وعند أول تشغيل، ينشئ حساب المدير الأعلى ويعرض بريده وكلمة مروره العشوائية **مرة واحدة** في Railway Logs تحت حدث `startup_admin_created`. احفظ بيانات الدخول فورًا؛ لن تُعرض كلمة المرور عند إعادة التشغيل اللاحقة. إذا عيّنت `ADMIN_PASSWORD` بنفسك، فلن يطبع التطبيق قيمتها في السجلات.

الإعدادات الاختيارية:

- `ADMIN_NAME`
- `ADMIN_PHONE`
- `ADMIN_EMAIL`
- `ADMIN_PASSWORD`
- `JWT_SECRET`
- `DB_PATH`
- `UPLOAD_DIR`
- `WHATSAPP_OTP_ENABLED` (معطّل افتراضيًا؛ يحتاج إلى إعداد مزود واتساب إذا فُعّل)

## الاختبارات المنفذة

```bash
npm test
```

التحقق الحالي شمل البناء، وفحص TypeScript، واختبارات تسجيل الدخول والتسجيل والصلاحيات وإدارة الكتالوج، والتأكد من أن الكتالوج النشط قسم واحد بتسع خدمات مركبات، واختبار البحث التقليدي وإنشاء طلب بنشر من عميل مسجل. **44 اختبارًا نجحت** في آخر تشغيل. كما اجتاز تشغيلًا فعليًا محليًا فحص الصحة، وإنشاء المدير الأول وتسجيل دخوله، وقراءة الكتالوج. لم يتم النشر إلى حساب Railway الخاص بك أو اختبار واجهة المتصفح في بيئة الإنتاج.
