# البنشر الذكي

منصة عربية RTL لخدمات البنشر والإطارات والمركبات، مبنية على Node.js دون حزم خارجية إلزامية حتى لا تتعطل عملية البناء بسبب `npm install` أو رابط قاعدة بيانات غير مضبوط.

## التشغيل المحلي

يتطلب Node.js 20 أو أحدث:

```bash
npm start
```

ثم افتح `http://localhost:3000`.

## النشر على GitHub وRailway

1. ارفع **محتويات هذا المجلد** إلى مستودع GitHub الحالي (لا ترفع ملف ZIP بدل الملفات).
2. اربط مستودعك الحالي بخدمة Railway، أو اترك الخدمة المرتبطة به كما هي.
3. في Railway → خدمة التطبيق → Variables، عيّن `ADMIN_PASSWORD` إلى كلمة مرور قوية وفريدة، وعيّن `ADMIN_NAME` إذا رغبت.
4. لا يلزم إعداد `DATABASE_URL` في هذه النسخة؛ فهي لا تستخدم PostgreSQL ولا تتصل بـ `localhost:5432`.
5. أمر التشغيل `npm start`، وفحص الصحة `/health`، وكلاهما محدد في `railway.json`.
6. لدوام البيانات عبر إعادة النشر، أضف Railway Volume واربطه بالمسار `/app/data`، ثم اترك `DATA_DIR=/app/data`. من دون Volume قد تُفقد بيانات JSON عند استبدال الحاوية أو إعادة نشرها.
7. افتح `/admin.html` وسجّل الدخول بكلمة المرور التي وضعتها في `ADMIN_PASSWORD`.

## الواجهات

- `/` واجهة العميل العامة.
- `/customer.html` طلبات العميل.
- `/provider.html` بوابة مقدم الخدمة.
- `/admin.html` لوحة الإدارة.
- `/health` فحص التشغيل.

## الوظائف المتاحة في هذه النسخة

- إنشاء حساب عميل أو مقدم خدمة والدخول برقم الهاتف (لا يوجد OTP فعلي بعد؛ خدمة الرسائل المدفوعة مؤجلة).
- إنشاء طلبات خدمات متنقلة أو طلب زيارة فرع، وتحديد وصف الموقع أو GPS عند سماح المتصفح.
- مسار حالات الطلب: جديد، مقبول، في الطريق، وصل، قيد التنفيذ، مكتمل، مع إلغاء قبل بدء التنفيذ.
- عروض أسعار للخدمات غير الثابتة وموافقة العميل أو رفضه.
- محادثة نصية مرتبطة بالطلب، تقييم بعد الإكمال، وشكاوى للإدارة.
- إدارة الهوية والألوان وأرقام التواصل والعملة، وإدارة الإعلانات الموسمية بتاريخ بداية ونهاية.
- إدارة الخدمات، أنواع المركبات، المنتجات والمخزون، الفروع، مقدمي الخدمة، حالات الدفع والشكاوى.
- واجهات PWA قابلة للتثبيت من المتصفح، وتخزين ملفات ثابتة بشكل محدود دون اتصال.

## حدود معروفة — لا تُخفى

- هذا الإصدار يستخدم ملف JSON بدل PostgreSQL، لذلك يصلح كبداية قابلة للنشر والاختبار ولا يوصى بتشغيله تجاريًا على عدة نسخ متزامنة دون نقل التخزين إلى قاعدة بيانات مُدارة.
- لا يوجد OTP/SMS حقيقي أو بوابة دفع أو دفع إلكتروني.
- تتبع الموقع يعمل عند فتح واجهة مقدم الخدمة فقط؛ لا نضمن تتبع الخلفية بعد إغلاق المتصفح.
- الخرائط والملاحة الحية، ورفع وثائق الهوية والتحقق الآلي منها، والتنبيهات الخلفية الفعلية تحتاج تكاملات إضافية واختبارات ميدانية.
- الدخول غير القائم على OTP مؤقت للاختبار. غيّر كلمة مرور الإدارة الافتراضية فورًا عبر `ADMIN_PASSWORD` قبل النشر، ولا تستخدم كلمة مرور مشتركة.
- بيانات الملف JSON لا توفر معاملات قاعدة بيانات متقدمة أو حماية تعارضات الكتابة؛ استخدم PostgreSQL قبل الإطلاق التجاري واسع النطاق.
